toyol Low-Level Design

How the overlay works inside: its modules, data types, the contract between the WebView and Rust, each runtime flow step by step, the state machines, and the algorithms behind voice, answers and autocomplete. It goes with the high-level diagram in docs/architecture/toyol-hld.drawio.

Small value types

  • InputSource = typed | voice | screen: tells the model how to read the input.
  • Tone = default | conversational | professional | simple | technical | custom.
  • ScreenRect {x, y, width, height}: physical px in virtual-screen coordinates.
  • SnipState = {first} or {second, anchor, pressed}.
  • HotkeyDef {id, action, scope: global | focused, default}: 11 global, 4 focused.
  • Suggestion {text, label, kind: question | phrase | word | next}.
  • Download (Rust, serde) {received, total}: the speech-download payload.

04Runtime flows

4.1 Ask and stream an answer

Every input path ends in App.send → useChat.ask: typed text, a follow-up click, a voice transcript, or a screenshot. Asking again while an answer is streaming aborts that answer and marks it stopped.

sequenceDiagram
  autonumber
  actor U as User
  participant C as Composer
  participant A as App
  participant H as useChat
  participant AI as lib/ai.ts
  participant S as AI service
  participant V as Conversation
  U->>C: Enter (or follow-up click)
  C->>A: sendDraft() decides typed or voice
  A->>A: rememberQuestion(text) if typed
  A->>H: ask(text, source, image)
  H->>H: abort previous controller, new AbortController
  H->>H: history = last 6 answered turns, old screenshots become a note
  H->>H: append Turn(thinking), mark running turns stopped
  alt endpoint, model or key missing
    H-->>V: Turn failed with "Add the AI service in Settings"
  else configured
    H->>AI: streamAnswer(settings, history + userMessage, onText, signal)
    AI->>AI: clientFor(settings), cached per endpoint and key
    AI->>S: POST /responses, instructions + tone, max_output_tokens 6000, stream
    loop each response.output_text.delta
      S-->>AI: delta
      AI-->>H: onText(text so far)
      H-->>V: patch Turn(writing, answer)

  end

4.2 Voice on this PC, transcribed while you talk

Whisper doesn't stream, so LiveTranscript re-transcribes the unsettled tail of the recording as it grows. A pass takes about a quarter of a second on a GPU. When the user stops, the last live pass has usually already heard everything.

sequenceDiagram
  autonumber
  actor U as User
  participant K as useHotkeys or mic button
  participant UV as useVoice
  participant R as recorder
  participant LT as LiveTranscript
  participant E as engine.localPasses
  participant RS as speech_transcribe
  participant SP as speech.rs
  U->>K: voice key Pressed
  K->>UV: keyDown()
  UV->>R: startRecording(micId, onLevel, onLimit)
  R->>R: getUserMedia with echo cancel, noise suppress, AGC
  R->>R: AudioContext 16 kHz, ScriptProcessor 2048 into a 120 s buffer
  UV->>LT: new LiveTranscript(localPasses, prompt, setLiveText)
  loop every 100 ms while listening
    UV->>LT: update(recordedAudio()), a view with no copy
    opt 0.3 s of new audio and no pass running
      LT->>LT: settlePoint(): 12 s unsettled and a pause found?
      LT->>LT: prepareSpeech: trim, normalize, split at 28 s
      LT->>E: pass(chunk, prompt + last 40 settled words, maxTokens, final)
      E->>RS: invoke with binary body and x-max-tokens, x-final headers
      RS->>SP: transcribe(Pass) on a blocking thread
      SP-->>RS: text, or None if cancelled
      RS-->>E: text or null
      E-->>LT: text
      LT->>LT: cleanTranscript(text, prompt)
      LT-->>UV: onText(settled + live), shown above the box
    end
  end
  U->>K: Released after 450 ms or more, or a second tap
  K->>UV: keyUp() then finish()
  UV->>R: stopRecording(), mic released
  UV->>LT: finish(audio)
  opt a live pass is running
    LT->>E: cancel()
    E->>RS: speech_cancel
  end
  LT->>LT: did the latest pass hear past the last word? if not, one final pass on the rest
  LT-->>UV: text
  UV-->>U: autoSend: send as voice, otherwise put the text in the box

With cloud transcription there is no live text. On stop, transcribeCloudSpeech runs the same prepareSpeech, joins the chunks, encodes a 16-bit WAV, calls /audio/transcriptions (language en, temperature 0, the same prompt), then cleanTranscript.

06Algorithms

6.1 The answer contract and its parser

The system prompt in ai.ts asks for a fixed Markdown layout. answer.ts parses it on every streamed delta, so it has to handle a reply cut off at any character.

Q: <the question as understood, one line> **<direct answer, ≤ 25 words>** - **<term>**: <point, < 15 words> (3–5 bullets) ← glance ## Details ← details (80–250 words) ## Follow-ups - **<likely next question>** <1–2 sentence answer> (2–3) ← followUps
RulePatternPurpose
Q line^\s*(?:\*\*)?Q:(?:\*\*)?\s*([^\n]*)(\n|$)Takes the question off the top. A body that is only Q or Q: so far is treated as empty.
Section heading^#{1,4}\s*\**\s*(details|follow[- ]?ups?)\s*\**\s*:?\s*$ (gim)Splits into sections. Repeated sections are concatenated.
Partial heading\n#{1,4}[^\n]*$Drops a heading that is still arriving (## Det) so it never flashes on screen.
Follow-up item^\s*(?:[-*]|\d+\.)\s+\*\*(.+?)\*\*\s*[:\-–—]?\s*(.*)$Bold text is the question (clicking it asks it), the rest is the answer. Lines that don't match continue the previous answer.

The tone setting only adds a wording rule after the instructions and says to keep the format exactly. History is the last 6 turns, and screenshots aren't sent again ("[screenshot sent earlier]"), which keeps follow-up requests small.

6.2 Live transcription (speech/live.ts)

ConstantValueRole
STEP_SECONDS0.3 sNew audio needed before the next live pass
SETTLE_AFTER_SECONDS12 sUnsettled audio longer than this gets settled
SETTLE_GAP_SECONDS1.5 sA pause must be at least this far from the end
MIN_SETTLED_SECONDS3 s…and at least this far from the start
HEARD_AFTER_SECONDS0.3 sThe last pass counts as final if it ran this long past the last word
CARRY_WORDS40Settled words carried into the next pass's prompt
MAX_CHUNK_SECONDS28 sHard cut at the quietest frame if there's no pause

Invariants

  • At most one pass in flight (running). Only live passes can be cancelled; settling passes always finish.
  • text() = settled.join(' ') + heard.text. Settled text never changes; the live tail is replaced on every pass.
  • A final pass on stop is needed only if heard.end < settledEnd + speech.end − PAD + HEARD_AFTER.
  • No speech after the last settle point means no final pass at all.

6.3 Audio conditioning (speech/audio.ts)

frames = RMS of 20 ms (320 samples) floor, loud = p10, p95 of frame levels no speech if loud < 0.004 (≈ −48 dBFS) or loud < 3·floor threshold = max(2.5·floor, floor + 0.12·(loud − floor), 0.002) trim = first..last voiced frame ± 0.25 s pad; voiced ≥ 0.15 s required normalize = gain min(30, 0.9 / p99.9(|x|)), clipped to [−1, 1] split = audio over 28 s is cut at the quietest frame in the 6 s before the limit pause = ≥ 0.3 s below threshold with speech on both sides (findPause scans backwards)

6.4 Whisper decoding (speech.rs) and transcript clean-up

Decode parameters

  • Greedy sampling, language = "en", single_segment, no_timestamps, no_context (the prompt carries the context).
  • temperature 0; temperature_inc 0.2 only on final passes, so only text that gets sent is retried when garbled.
  • suppress_blank, suppress_nst (no "[music]").
  • n_threads = clamp(cores, 2, 8); max_tokens = min(220, ⌈6·seconds⌉ + 24).
  • whisper.cpp logs below WARN are dropped.

Prompt and clean-up (transcript.ts)

  • Prompt = the vocabulary list as a sentence, then the last question, ending with a full stop. At most 600 characters, cut at a word break so the vocabulary is kept.
  • Bracketed tags, music notes and leading subtitle dashes are removed.
  • Any 1–12 word phrase repeated 3 or more times in a row is collapsed to one copy.
  • A transcript that is only a "silence phrase" ("thank you", "thanks for watching"…) becomes empty.
  • A transcript over 12 characters that appears inside the prompt is an echo and is discarded.

6.5 Cancelling passes without a channel

Each transcribe takes a number from next_pass.fetch_add(1). cancel() sets cancelled_through = max(it, next_pass − 1). A pass checks number ≤ cancelled_through three times: before it starts, through whisper's abort_callback while decoding, and after decoding. A pass waiting on the mutex therefore gives up as soon as it gets the lock, and passes started after the cancel are not affected.

6.7 Reading-pace auto-scroll and keyboard control

useAutoScroll

  • A new turn is scrolled to the top at once (scrollIntoView, instant).
  • Pace: slow 0.6, medium 1, fast 1.6 lines a second; a line is font-size × 1.5.
  • Starts after reading 5 lines takes at that pace; keeps waiting while the answer is still being written.
  • The user takes over on wheel, pointerdown or keydown, or when scrollTop moves more than 4 px from where the hook put it.
  • Frame time is capped at 100 ms so a hidden panel doesn't jump when shown again.

Shortcuts

  • Accelerators are stored as Ctrl+Alt+Shift+<KeyboardEvent.code>. Global ones default to Ctrl+Alt+Shift because Teams and Zoom leave that combination free.
  • Registrations go through a serial promise queue and start with unregisterAll(), so keys are never left bound to a dead page after a reload.
  • Only the voice key uses both Pressed and Released.
  • takeKeys adds key repeat in software (300 ms delay, then every 30 ms), because Windows hotkeys don't repeat.

10Security and privacy

What leaves the PC

  • Questions, the last 6 turns, and screenshots the user takes: only to the configured AI endpoint.
  • Voice recordings only with cloud transcription. Local Whisper keeps audio on the machine.
  • Update checks to GitHub and the one-time model download from Hugging Face.

Controls in the code

  • Model output is rendered with marked, then sanitized by DOMPurify. Links carry no href, so they can't navigate the panel.
  • Updates must be signed with the minisign key whose public half is in tauri.conf.json.
  • The model is pinned to a revision and checked by SHA-256 (43fa2cd0…f11c).
  • The panel and snip window are hidden from screen capture by default.
  • The microphone is granted without a prompt but is open only while listening.
Known trade-offs. The API key is stored in plain text in config.json, and the OpenAI SDK runs in the WebView with dangerouslyAllowBrowser. The app is local and single-user, so the key stays with its owner, but anything that can read the user's AppData can read it. Windows Credential Manager would be the next step. With CSP off, the sanitizer is the main defence if model output ever contains markup.
